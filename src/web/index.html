      Technical report, arXiv 2412.19437, December 2024, DeepSeek-AI

      DeepSeek-V3 Technical Report

      DeepSeek-V3 is a mixture-of-experts language model, which means each token is sent to a few small sub-networks called experts. The model has 671B parameters and uses 37B of them for each token. The main new ideas are keeping the experts evenly loaded without an extra loss term, training the model to also predict the token after next, and running most of the training math in 8-bit floating point (FP8). The authors also overlap network communication with computation, so the GPUs spend less time waiting.

      37Bparameters used per token
      14.8Tpre-training tokens
      61layers
      128Ktokens of context
      2.788MH800 GPU hours

      Router simulation of load balancing without an auxiliary loss

      0training steps
      0busiest expert load / average load
      0experts below half the average load

      What to notice: With no balancing, a few popular experts get most of the tokens, so the other experts get few tokens to learn from. With bias adjustment, an expert's bias goes down when the expert gets too many tokens, and it goes up when the expert gets too few. As a result, the loads move close to the even share within a few steps. The bias only changes which experts the router picks, and the output weights still use the scores without the bias. Because of the split, the model needs no extra loss term for balance. The simulation uses 16 experts and picks 2 per token, while DeepSeek-V3 uses 256 routed experts and 1 shared expert and picks 8 routed experts per token. DeepSeek-V3 also keeps a very small balancing loss for each sequence (α = 0.0001), which prevents extreme imbalance inside one sequence.

      What to notice: The KV cache holds the keys and values of earlier tokens, so the model doesn't recompute them for each new token. For each token and layer, MLA stores 576 numbers, which are a compressed vector of 512 numbers and a position key of 64 numbers.       Multi-token prediction

      tokens already seen main head target (t+1) MTP target (t+2)

      What to notice: Each position gives two training targets, which are the next token for the main head and the token after it for the MTP module. The MTP module takes the main model's hidden vector and the embedding of the next token, so each prediction still only uses earlier tokens. When the model generates text, the MTP module can be removed. It can also be used for speculative decoding, where the model proposes the second token early and checks it in the next step. The paper reports that 85 to 90% of the proposed second tokens are accepted.

      The FineWeb Datasets: Decanting the Web for the Finest Text Data at Scale
      
      
      FineWeb is an open English web dataset of 15T tokens, built from 96 snapshots of Common Crawl, which is a public archive of web pages.       Systems paper, arXiv 2205.14135, May 2022, Stanford University and University at Buffalo
      
      
      FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness
      
      
      FlashAttention computes exact attention faster by reading and writing the GPU's main memory less often. Standard attention writes the full N×N score matrix to the GPU's main memory, called HBM, and reads it back. For long sequences, the memory traffic takes more time than the arithmetic. FlashAttention splits the inputs into tiles that fit in the small, fast on-chip memory, called SRAM. It combines the tiles one at a time with an online softmax, so the N×N matrix is never stored in HBM. The paper also counts HBM reads and writes to analyze attention, and it proves that FlashAttention needs fewer of them than standard attention.
      
      
      
        
      7.6×faster attention on GPT-2
      
        
      3×faster GPT-2 training
      
        
      15%faster BERT-large training
      
        
      64Klongest sequence tested
      
        
      Exactsame output as standard attention
      
        
      O(N)extra memory for N tokens

      Why standard attention is limited by memory traffic
      
        
      A GPU kernel is limited either by arithmetic or by memory traffic, and the slower of the two sets its run time. The paper shows that for attention, memory traffic is the limit.
      
      
      
      
      
        
      
          
      Figure 1 of the paper
      Memory hierarchy of an A100 GPU
      
        
      
        
      
          
      
          
      The bar length uses a log scale for bandwidth.
      
          
      What to notice: SRAM is more than 10 times faster than HBM, but it holds about 2,000 times less data. Standard attention keeps its N×N matrices in HBM, because they don't fit in SRAM for long sequences.

      A roofline estimate compares the time to move the data with the time to do the arithmetic, and the larger time is the limit. The estimate uses the A100's peak rates of 312 TFLOPS (trillion floating point operations per second) for FP16 matrix math and 1.5 TB/s for HBM. It counts 2 bytes per number, and real kernels run below the peak rates, so the times are lower bounds.
      
          
      What to notice: The softmax step reads and writes the whole N×N matrix but does very little arithmetic on it. For every step and every setting in the calculator, moving the data takes longer than the arithmetic, so standard attention is limited by memory traffic.
      
        
      
      
      
    
      
    
      
      
      
        
      How FlashAttention computes attention one tile at a time
      
        
      FlashAttention loads one block of K and V into SRAM and then loops over the blocks of Q. For each pair of blocks, it computes the scores, updates the softmax statistics, and adds to the output, so it never writes a full N×N matrix to HBM.
      
      
      
      
      
        
      
          
      Interactive animation
      Loop over the tiles of the N×N score matrix
      
          
      
        
      
        
      
          
      
            
      
              
      K and V blocks, outer loop →
      
              
      Q blocks, inner loop
      
            
      
            
      
          
      
          
      What to notice: Each block of K and V is read from HBM once, while the blocks of Q and O are read once for every block of K and V. Each tile of scores exists only in SRAM while the kernel uses it, so the kernel never writes an N×N matrix to HBM.
      
        
      
      
      
      
      
        
      
          
      Interactive example
      Online softmax for one row of scores
      
          
      
        
      
        
      
          
      Each position has a score s and a value v, and the output is the softmax average of the values. The kernel sees the scores in blocks of 2.
      
          
      
          
      m_new = max(m, block scores), ℓ_new = e^(m - m_new) × ℓ + Σ e^(s - m_new), o_new = (e^(m - m_new) × ℓ × o + Σ e^(s - m_new) × v) / ℓ_new
      
          
      
          
      
          
      What to notice: The running output after each block is the correct softmax average of the scores seen so far. When a new block has a larger score, the factor e^(m - m_new) rescales the earlier sum and output. As a result, the output after the last block equals the standard softmax over the whole row.

      Missing information
      Limits of the evidence
      
        
      
        
      
          
        
            
      • The analysis covers the memory hierarchy of one GPU, and it doesn't cover attention that is split across several GPUs.
        • 
            
      • The block sizes are chosen for the A100, so speedups on GPUs with less SRAM can be smaller.
        •
